# Scaling Airbnb’s identity graph with a unified knowledge graph infrastructure

## Introduction

Airbnb’s identity graph is a large-scale graph data product designed to map relationships between users for identity resolution and relationship understanding. Serving as a critical foundation layer for Trust and Safety operations, the system manages one of the largest graph datasets within the organization. In 2024, Airbnb transitioned this infrastructure from an external Platform-as-a-Service model to a unified, internally managed knowledge graph platform to address growing complexity and scale. This architectural shift enables key use cases such as detecting suspicious activities and identifying linked accounts, enhancing fraud prevention and platform security. The documentation outlines the engineering foundations, challenges, and optimizations involved in migrating the identity graph to this new paved-path architecture for enterprise-scale adoption.

## Core Concepts

### The Function and Purpose of the Identity Graph
*   **Relationship Mapping:** The graph captures relationships between users by modeling them as vertices (users) and edges (relationships).
*   **Trust and Safety Application:** It serves as a critical foundation for Trust and Safety use cases, such as detecting suspicious activities and identifying linked accounts.
*   **Identity Resolution:** The system provides aggregated insights that enable user identity resolution and a deeper understanding of user relationships.
*   **Scale and Complexity:** It stands as one of the largest and most complex graph data products at Airbnb, requiring support for significant scale and complex queries.

### Strategic Shift to Unified Infrastructure
*   **Internal Management:** Airbnb is transitioning from relying on PaaS (Platform as a Service) to an internally managed, paved-path graph data platform.
*   **Unification Goal:** The new infrastructure aims to create a unified knowledge graph base that can serve multiple systems, with the identity graph being one of the first adopters.
*   **Scalability Focus:** This investment addresses the growing challenges associated with the storage and query complexity of the identity graph over time.

### Core System Architecture
*   **Graph Data Storage:** The storage layer utilizes a combination of a graph database and a key–value (KV) caching layer to model data efficiently.
*   **Graph Service Layer:** This component provides a unified interface for accessing graph data, acting as the intermediary between the storage backends and the applications.
*   **Logic Application:** The service layer is responsible for retrieving data from underlying sources and applying necessary aggregation logic or models before returning results.

### Data Flow and Performance Requirements
*   **Real-Time Ingestion:** Most data within the identity graph is ingested via asynchronous events in near real-time.
*   **Low-Latency Serving:** The system is designed to fulfill service calls with low latency, ensuring real-time responsiveness for safety applications.
*   **Distributed Access:** Data is served through real-time service calls that fetch information from the underlying storage sources through the unified graph service.
